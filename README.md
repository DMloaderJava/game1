# GRAVITY: VOID — итерация 1A (добыча и инвентарь)

Две точки входа, обе открываются двойным кликом:

| Файл | Что это |
|---|---|
| **`index.html`** | Игра на весь экран — это то, что открывается по умолчанию. |
| **`gravity-void.html`** | Сама игра, один файл. Без npm, CDN и внешних ассетов. |
| **`review.html`** | Ревью 1A: вердикт, дефекты, скоуп, must-fix, вопросы, 9 скриншотов. Отдельным файлом, чтобы не мешать игре. |

Игра вместо пустого экрана при сбое выводит экран диагностики с причиной ошибки (`#fallback`).
Ревью — обычный HTML со скриншотами: оно читается, даже если игра не запустилась.

## Запуск

- Игра: открыть `index.html`. Клавиатура подхватывается сразу (фокус передаётся игре при загрузке, по движению мыши и по клику).
- Ревью: открыть `review.html`.

Управление (как в Milestone 0):
`A` / `D` — идти · `Space` — прыжок · `F` — переворот гравитации ·
`ЛКМ` — копать тайл / тянуть тело · `ПКМ` — толчок тела

## Решения, которые стоит проверить на ревью

1. **Конфликт ЛКМ решён приоритетом тела.** Нажатие ЛКМ сначала ищет тело (дроп/ящик)
   в точке курсора; если есть — захват телекинезом, иначе — копание. Удерживаемое тело
   подсвечивается и соединено с игроком пунктирным тросом.
2. **«3 удара» для камня = 0.5 с удержания.** В задании одновременно «копается за 3 удара»
   и «время копания 0.5 с». Сделал одно удержание, а «удары» показываются как растущие
   трещины (1 → 3). Так копание одинаково устроено для всех тайлов.
3. **Масштаб 2×.** При 32 px и масштабе 1:1 на 1280 px видно 40 тайлов, и мир читается как
   мелкая сетка. С масштабом 2× видно ~20 тайлов — тайл превращается в «клетку», персонаж
   в 22×28 px перестаёт быть точкой. Параметр — `CFG.camera.zoom`.
4. **Сетка еле видна (alpha 0.06).** Прицел и радиус считаются по тайлам, поэтому границы
   клеток должны угадываться, но не превращаться в «клетчатое одеяло».
5. **Тайлы статичны** (как в задании): обвал породы не делал, риск завалов и лишняя физика.

## Как проверялось

Всё, что ниже, — воспроизводимо, браузер не нужен.

```bash
cd tools
npm i @napi-rs/canvas   # только для скриншотов
node verify.mjs         # 45 автопроверок логики и физики
node screenshots.mjs    # рендер 8 кадров в ../screenshots
```

`tools/verify.mjs` прогоняет игру через заглушки DOM/Canvas в Node и проверяет буквально
критерии приёмки: генерацию мира, ходьбу, прыжок, копание всех типов тайлов с таймингом,
спавн/падение/сон/подбор дропов, «далеко», телекинез ящика и дропа, переворот гравитации
(игрок на потолке, не застревает, дропы падают вверх и не проваливаются сквозь плиту),
отсутствие застревания в тайлах, HUD-пульсацию, а также то, что в простое offscreen-буфер
тайлов не перерисовывается (0 вызовов `fillRect`, 1 `drawImage` на кадр).

Текущий статус: **45/45 проверок пройдено**.

Скриншоты: `screenshots/01-start.png` … `08-cave.png`
(старт, копание, HUD, 55 тел на полу, телекинез, потолок, «далеко», пещера после раскопок).

**Производительность** (headless-замер JS+draw, не браузерный FPS):
старт — 66 мс, кадр `p50 ≈ 4.8 мс`, `p95 ≈ 5.2 мс`; выброс только на первом кадре.
Счётчик FPS и числа тел есть на экране слева сверху — по нему проверяется критерий в браузере.

Кэш: буфер тайлов 6400×3200 (≈78 МБ VRAM). Силуэт рисуется сразу, текстура — лениво,
только для тайлов в кадре, с бюджетом 3 мс/кадр (`CFG.render.detailBudgetMs`),
поэтому запуск не «висит».

## Ответы на «интерфейс обратной связи»

1. **Ощущается ли прогресс копания интуитивным?** Да, за счёт трёх дублирующих сигналов
   (заливка тайла, трещины, полоса). Что бы изменил: добавил бы микро-тряску камеры
   на последних 20 % тяжёлого тайла (`STONE`/`FERRITE`) — сейчас тяжёлые тайлы ощущаются
   так же, как земля, только дольше.
2. **Артефакты при большом количестве дропов?** Да, на 50+ дропах лежит «полоса» из
   квадратов, и `DIRT`-дропы почти сливаются с землёй того же цвета. Блик и тень помогают,
   но это всё ещё шум. Кандидат: у дропов светлая обводка 1 px + они не должны лежать
   более ~20 штук без подбора (магнит подбора в радиусе 1.5 тайла).
3. **Мешает ли телекинез копанию?** Приоритет тела спасает от случайного захвата, трос
   объясняет, что происходит, но при копании у ног дроп может «перехватить» нажатие — это
   раздражает. Кандидат на решение: копание — ЛКМ, телекинез — ПКМ, толчок — `Shift`+ПКМ.
   Это решение по управлению, поэтому сам не менял.
4. **Какой вопрос к геймдизайнеру важен перед 1B?** Можно ли ставить блок «в воздухе»,
   если он не касается ни тайла, ни пола? От этого зависит, станет ли стройка лестницами
   в небо (и нужен ли тогда запрет/гравитация постройки).

## ЗАПРОСЫ РЕВЬЮ

1. **Сколько тайлов должно быть видно по горизонтали?** Сейчас 1280 px / (32 px × 2×) ≈ 20.
   Больше — мельче персонаж, меньше — теснее при копании и стройке. Это `CFG.camera.zoom`.
2. **Нужно ли «провисание» породы после копания?** Если да — это отдельная подсистема
   (и она сильно меняет 1B: стены придётся строить с опорой). Если нет — фиксируем статику.
3. **Дропы при перевороте гравитации улетают к потолку и копятся там.** Оставляем как есть
   (физика!) или вводим магнит подбора, чтобы ресурс не терялся?
4. **Радиус копания 4 тайла считается от центра игрока.** При копании под собой это
   фактически 5+ тайлов по вертикали. Мерить от центра или от «ног»?

## Структура файла

`CFG` (все числа) → `World` (сетка) → `TileLayer` (offscreen-рендер тайлов) →
физика (`resolveX/Y`, `moveAndCollide`) → `PhysBody`/`Crate`/`Drop` → `Player` →
`Particles` → `Inventory` → `Camera` → `Input` → `Game` (update/render/HUD).

Комментарии — по-русски, только по делу. `console.*` в файле нет.
